# 既存コード調査

### 事実

- `JEPA.encode` は `info["pixels"]` を encoder に通し、`last_hidden_state[:, 0]` の CLS token を `projector` に通した結果を `info["emb"]` として格納する。出典: `jepa.py:29`、`jepa.py:34`、`jepa.py:37`、`jepa.py:38`、`jepa.py:39`、`jepa.py:40`。
- `JEPA.encode` は `info` に `action` が存在する場合、`action_encoder` の出力を `info["act_emb"]` として格納する。出典: `jepa.py:42`、`jepa.py:43`。
- `JEPA.predict` は latent embedding `emb` と action embedding `act_emb` を `predictor` に通し、`pred_proj` を通した出力を future latent embedding として返す。出典: `jepa.py:47`、`jepa.py:52`、`jepa.py:53`、`jepa.py:54`。
- 学習時の `lejepa_forward` は `self.model.encode(batch)` で得た `emb` から context embedding を作り、`self.model.predict(ctx_emb, ctx_act)` で予測 embedding を作る。出典: `train.py:27`、`train.py:29`、`train.py:32`、`train.py:33`、`train.py:35`、`train.py:36`。
- LeWM の学習 loss は prediction MSE と SIGReg loss の和である。出典: `train.py:38`、`train.py:39`、`train.py:40`、`train.py:41`。
- 公式 main の現行 training code は `hydra.utils.instantiate(cfg.model)` で model を構築し、LeWM model 定義は `config/train/model/lewm.yaml` に分離されている。出典: `train.py:85`、`config/train/model/lewm.yaml:1`。
- TwoRoom training config は `pixels`、`action`、`proprio` を `keys_to_load` に含める。出典: `config/train/data/tworoom.yaml:5`、`config/train/data/tworoom.yaml:6`、`config/train/data/tworoom.yaml:7`、`config/train/data/tworoom.yaml:8`。
- TwoRoom evaluation config は state に `proprio`、goal state に `goal_proprio` を使う callable を指定している。出典: `config/eval/tworoom.yaml:32`、`config/eval/tworoom.yaml:33`、`config/eval/tworoom.yaml:34`、`config/eval/tworoom.yaml:38`、`config/eval/tworoom.yaml:39`、`config/eval/tworoom.yaml:42`。
- planner cost は rollout された predicted embedding の最後の step と goal embedding の最後の step の MSE sum である。出典: `jepa.py:112`、`jepa.py:117`、`jepa.py:119`、`jepa.py:120`、`jepa.py:121`、`jepa.py:122`、`jepa.py:124`。
- `rg -n "probe|Probing|linear|MLP|physical|room|goal|latent|effective|intrinsic|rank|reachability|cost|decoder" .` を `260522-lewm-tworoom-diagnostics` worktree で実行した範囲では、このリポジトリ内に probe 実験スクリプトは確認されなかった。該当した実装ファイルは `module.py` の汎用 `MLP`、`jepa.py` の latent/cost、`eval.py` の goal 処理、README の説明である。

### 現在検討中の点

- `proprio` から agent 座標、room ID、goal までの相対位置を作る具体的な列定義は未確認である。
- Hugging Face mirror の `weights.pt` と `config.json` を使う場合、README の変換手順で `_object.ckpt` を作る必要がある。出典: `README.md:137`、`README.md:139`、`README.md:140`、`README.md:143`、`README.md:174`、`README.md:177`。
- encoder 出力 `z_t` と predictor rollout 出力 `\hat{z}_{t+k}` は別の診断対象として扱う必要がある。

### 採用方針

- `a: 表現情報量` では、観測画像 `o_t` から `JEPA.encode` で得られる `info["emb"]` を primary latent として probe する。
- predictor を通した latent は `c: multi-step dynamics の精度` の診断対象に分離する。
- `d: planner cost の整合性` では、現行 `JEPA.criterion` の terminal latent MSE cost と環境上の到達可否・最短経路量との対応を評価対象にする。
