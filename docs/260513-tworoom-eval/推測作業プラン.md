## 1. 目的と再現目標値

- 論文 `fig:ctrl-all` の Two-Room パネルにおける LeWM の Success Rate 値を再現する。

### 1.2 目標値
- **LeWM @ Two-Room: SR = 87%**
- 根拠: `papers/2603.19312_leworldmodel/source/figs/ctrl-two-room.pdf`（本ブランチ内 `tworoom_fig.png` に画像として保存）。
  - 同図に併記される他手法値: PLDM=97, DINO-WM=100, DINO-WM+prop=100, GCBC=100, GCIQL=100, GCIVL=100, Random=0。

- 評価は 50 試行（後述）。本研究の目標値は誤差込みでこの近傍に乗ること。

| 項目 | 論文記載値 | 出典 |
|---|---|---|

| image size | 224×224 |

## 6. 評価実行プラン（推測）

### 6.1 最小再現コマンド（README L77-85 準拠）
```bash
python eval.py --config-name=tworoom.yaml policy=tworoom/lewm
```
ただし、3 節の差分修正を **eval 起動前に必ず反映** する。

### 6.2 修正が必要な yaml（候補；確定作業プランに昇格させる前提）
- `config/eval/tworoom.yaml`
  - `eval.eval_budget: 50 → 150`
  - `eval.goal_offset_steps: 25 → 100`
  - `world.frame_skip` の意味を実装確認し、必要なら `5` に変更
- `config/eval/solver/cem.yaml`
  - **Two-Room 用に分離**するのが望ましい。例: `cem_tworoom.yaml` を作り `n_steps: 10` にして `config/eval/tworoom.yaml` の `defaults: solver: cem_tworoom` に書き換える。
  - 既存 `cem.yaml` を Two-Room 用に直接書き換えると PushT 等の他環境評価が壊れるため、**solver yaml は分離する** 方向を推奨。
- 予測器 history_size の経路（要確認 C2）について実装を確認の上、必要なら eval 側で明示指定する。

### 6.3 評価実行手順
1. データセット・checkpoint を `$STABLEWM_HOME` に配置。
2. 上記 yaml 修正を当てる。
3. `python eval.py --config-name=tworoom.yaml policy=tworoom/lewm` を実行。
4. `tworoom_results.txt` に書き出される `metrics` を確認。
5. 再現値 87% ± 数 pp を確認。乖離があれば 4 節の C1–C5 を順に潰す。

### 6.4 想定実行時間
- 論文 (`paper.cleaned.md` L185, L189): LeWM の planning は 1 試行 1 秒未満（PushT で測定）。Two-Room は episode あたり最大 150 env step、planning 6 ラウンド程度。50 試行 × 6 ラウンド × CEM 10 iter × 300 samples の規模で**数分〜十数分**程度と見込む（**要実測**）。

## 7. リスクと不確実点

| ID | 内容 | 対応案 |
|---|---|---|
| R1 | 予測器 history_size がコード経路で 1 に確実に渡らない場合、Two-Room checkpoint のロードはできても planning rollout が誤動作する可能性 | C2 を最優先で確認。stable-worldmodel の `WorldModelPolicy` / `PlanConfig` / `AutoCostModel` の実装を読む |
| R2 | HF 上の Two-Room データセット名・配置と yaml `dataset_name: tworoom` の一致が未検証 | データ取得時に HF ページで確認 |
