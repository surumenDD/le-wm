## F0. 結論サマリ（実行前に取るべき判断）

1. **モデルロードは `swm.wm.utils.load_pretrained` 経由が正**。`AutoCostModel` は legacy パス（`_object.ckpt`）であり、HF 配布形式（`weights.pt`+`config.json`）には対応していない。本リポ `eval.py` は `AutoCostModel` を使うため **置換が必要**。または stable-worldmodel 同梱の `scripts/plan/eval_wm.py` を直接利用。
2. **HF model id をそのまま policy 名に渡せる**: `policy=quentinll/lewm-tworooms`。`load_pretrained` が自動で `$STABLEWM_HOME/checkpoints/models--quentinll--lewm-tworooms/` に DL する。
3. **`history_size` は実装上 3 固定**。論文 Appendix の「Two-Room は 1」は **公開コードに反映されていない**。`PlanConfig.history_len` は CEM/LeWM の経路に伝播しない。再現は **3 で良い**（HF 学習済み model も `num_frames=3` で学習済み）。
4. **`eval_budget=50`, `goal_offset_steps=25`, `cem.n_steps=30` は公式 config と一致**。論文 Appendix F.1 の `150/100/10` とは **公式コード側が乖離**しており、公開チェックポイント＝公式コード前提なら **公式 config の数値を採用するのが整合**。
5. **`world.frame_skip` / `world.history_size` キーは `swm.World.__init__` が引数として持たない**。`**kwargs` で `gym.make` に流れて無視される可能性が高い。frame skip は `plan_config.action_block` で実現される。
6. **データセット名は `tworoom.h5`**（公式 config）。HF 配布の `tworoom.tar.zst` を **事前に zstd 展開** し `$STABLEWM_HOME/datasets/tworoom.h5` に置く必要がある（`load_dataset` の HF 自動 DL は `.h5` 直配置のみサポートで `.tar.zst` には未対応）。
7. **callables の column 名は `proprio` が正**（TwoRoom env の info キー）。公式 `scripts/plan/config/tworoom.yaml` の `pos_agent` 表記はおそらく古いデータ世代の名残。本リポ既存 yaml の `proprio` のままで問題なし。
8. **目標値 87% は LeWM の Two-Room 値**（`papers/2603.19312_leworldmodel/source/figs/ctrl-two-room.pdf` 描画結果より確定済み）。比較で PLDM=97, DINO-WM=100。

## F4. `world.frame_skip` / `world.history_size`

### F4.1 `World.__init__` は受けない
```
/home/ryo52/workspace/exp-wp/stable-worldmodel/stable_worldmodel/world/world.py:100-127
    def __init__(self, env_name, num_envs, image_shape, max_episode_steps=100,
                 goal_conditioned=True, extra_wrappers=None,
                 image_transform=None, goal_transform=None,
                 image_resample=None, **kwargs):
        ...
        env_fn = partial(_make_env, env_name, max_episode_steps, wrappers, **kwargs)
```
- `frame_skip` / `history_size` の名前付き引数なし → `**kwargs` 経由で `_make_env` → `gym.make(env_name, ..., **kwargs)` に渡る。
- `gym.make` が未知 kwarg を許す挙動は env 側依存だが、TwoRoom env (`envs/two_room/env.py:33-38`) の `__init__` は `render_mode`, `render_target`, `init_value` のみ受理 → `frame_skip` / `history_size` を渡すと **gym 側で TypeError か無視のどちらか**（**未検証**: gymnasium のバージョン差で挙動が変わる可能性）。
- 公式 `scripts/plan/config/tworoom.yaml` には `frame_skip` / `history_size` を含まない → **本リポ既存 `config/eval/tworoom.yaml:10-11` の `history_size: 1` / `frame_skip: 1` は削除すべき**。

### F4.2 frame skip の実体は `action_block`
- CEM solver は `action_dim = action_space_dim * action_block`（`solver/cem.py:79`）で候補を生成。
- `WorldModelPolicy.flatten_receding_horizon = receding_horizon * action_block`（`policy.py:362`）で env step 単位に展開。
- **`action_block=5`**（公式 config 通り）で frame skip = 5 が再現される。
